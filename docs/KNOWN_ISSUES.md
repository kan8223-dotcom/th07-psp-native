# 既知の不具合・未検証項目

## タイトル・デモの未検証経路

- **タイトル画面の背景・ロゴ・キャラクター・項目が欠落する問題（修正済み）。**
  直前の実機候補EBOOTでは背景だけ残ってANM表示が消える状態をPPSSPPでも再現しました。
  さらに全画面画像のEDRAM高速化を最初に組み込んだ版では、テクスチャアドレスを
  フレームバッファ同様の相対値へ変換していたため全面が黒くなりました。`sceGuTexImage`へ
  uncached絶対アドレスを渡すよう修正し、背景、タイトルロゴ、霊夢、8項目、説明、下部表記を
  起動直後、デモ手動中断後、Music Room復帰後の3経路でPPSSPP目視確認済みです。
  v0.1.4-betaのPSP-1000実機試験では、通常起動とResult画面からのタイトル復帰を確認しました。
- **タイトル放置デモをボタンで中断するとクラッシュする問題（修正済み、実機確認待ち）。**
  テストプレイヤー環境と手元の実機で再現しました。初回起動後にタイトル画面を
  操作せず待機して開始したデモは、最後まで自動再生させれば正常にタイトルへ戻りますが、
  デモ中にボタンを押して手動中断するとタイトル再登録の途中で終了していました。
  手動中断でも自動終了と同じく、その場でcalc chainを抜けるよう修正済みです。
  PPSSPPでは`自動終了 -> タイトル復帰`を1回、`ボタン中断 -> タイトル復帰`を
  2回連続で完走しています。v0.1.4-betaでは、両経路のPSP実機連続試験が残っています。

## 実機で報告された処理落ち

- v0.1.1-betaで追加した敵occupancy mapが、初期ECL中に3体を同期生成する4面ボスの親スロットを
  上書きし、遭遇会話後に戦闘が始まらない問題を起こしていました。初期ECL実行前に親スロットを
  確保するよう修正し、PPSSPPで後続スペルと4面突破、PSP実機で△早送り後の戦闘開始を確認済みです。
- 修正版のPSP実機試験では4面が通常60 FPSで動作することを確認しました。

- 1面ボス戦は通常時には滑らかですが、ボスのスペル発動で立ち絵カットイン、背景切替、
  Effectが重なる瞬間に数秒間重くなります。
- 4面は雲の上の3D背景へ切り替わった時点から重く、弾が増えるとプレイ困難になります。
- プリズムリバー戦付近の「霊界の門」では常時約30 FPSとの実機報告があります。
- 5面は階段程度の3D背景でも重くなります。

v0.1.4-betaでは、次をまとめて適用しています。

- 3D背景インスタンスをZ層ごとに一度だけ分類し、全インスタンスの4重走査を廃止。
- 3D背景のカリング半径をオブジェクト単位で再利用。
- 毎フレーム同一内容だったquad index生成を省略。
- 表示用の2枚のフレームバッファをRGBA8888からRGB565へ変更し、全画面の塗り・blend・
  表示転送帯域を半減。余ったEDRAMは640x480背景のRGB565キャッシュへ使用。
- UI、Item、Effect、非回転敵などの軸平行スプライトは汎用4頂点の構築・再走査を通さず、
  PSPネイティブ頂点へ直接出力。シーン遷移中のローディング描画にも使えるよう、頂点
  バッファは必要時に安全に初期化。
- 弾、敵、Effect、Item、自機弾の巨大な固定配列で空き要素本体を読まないoccupancy mapを追加。
- 回転角が変わらない弾のsin/cosを再利用し、完全に画面外の弾は4頂点を作る前に除外。
- ボム判定済みの弾が同じbomb-clear配列を直後にもう一度走査する処理を除去。
- 2026-08-09の実機ログでは、4面の弾約600発以上で約37～44 FPS、6面では背景表示後に
  弾が少なくても約56 FPS、弾約280～575発で約30 FPSまで低下することを確認。CPU側の
  draw chainが最大約13.6 msを占めていたため、ANM頂点を汎用形式からGU形式へ毎フレーム
  再走査・再コピーする経路を廃止し、PSPネイティブ頂点を直接GEへ渡すよう変更。

PPSSPPではネイティブ頂点化とRGB565フレームバッファ適用後も回転弾、通常弾、3D背景、
HUD、タイトル、Result、Music Roomの表示を目視確認しています。通常タイトルの確保・解放を
経由する6面診断では、6面ロード完了後、弾536・Effect 122付近まで継続し、定常60 FPSでした。
FPS改善量はPSP実機で4面雲上、霊界の門、5面階段、6面、スペル開始を再計測します。

v0.1.1-betaの3D背景頂点事前変換では1面の木の欠落、地形・フォグ表示、2面以降の背景に
回帰が発生したため、v0.1.3-betaでモデル行列、カメラ向きカード、フォグ計算、行列送信、
スペル中の背景層を最適化前の正確な経路へ戻しました。Z層分類とカリング半径キャッシュだけを
表示結果に影響しない背景最適化として残しています。

## Music Room

- 実機では入室が遅く、入室後も約19 FPS、曲開始も遅く、戻るとXMBへ終了するとの報告が
  あり、2026-08-09の再試験では入室完了まで待っても画面が切り替わりませんでした。
  実機を停止させる疑いのあるPSP JPEGハードウェア展開を廃止し、ユーザー所有の
  `th07.dat`から生成した640x480 RGB565キャッシュを先に読みます。全画面背景は従来どおり
  フレーム／深度バッファ後方の未使用EDRAMへ保持します。キャッシュ非搭載時だけ
  SDL_imageへフォールバックします。
- 曲名は選択行を優先し、画面に見える10件を1更新1行で作ります。スクロール時も新しく見える
  行だけを同じ方式で追加します。初期コメントと曲変更後のコメントは消さず、曲名生成後に
  1更新1行で描画します。文字アトラスは更新行だけを2つのGE参照アドレスへ同期し、同寸
  RGBA8888更新はピクセルごとの64bit座標除算を行わず行単位コピーします。
  PPSSPPでは2曲目のBGM開始と説明更新が最大250 msの計測窓へ
  分散され、その次の窓から60 FPSへ復帰しました。
- 戻る際はBGM停止キューを完了させ、draw chainを先に切ってからsurface/ANM/text cacheを
  解放します。PPSSPPの通常タイトル経路ではMusic Roomからタイトルへ復帰し、背景・ロゴ・
  メニュー再表示まで確認済みです。RGB565キャッシュ経路でも`music added ready`、背景・10曲・
  初期コメント、60 FPS安定、タイトル復帰を確認済みです。入室停止、19 FPS、XMB落ちの
  解消は実機で再確認待ちです。

## デバッグ版Practice

- `TH07_PSP_PERF_DIAG`付きEBOOTだけPracticeのクリア数ゲートを6面まで開放します。
  `clrd`、`pscr`、`score.dat`は変更しません。PPSSPPでは未クリア状態から6面を選択し、
  `data/stg6bg.anm`登録と6面ボス戦まで到達済みです。通常／リリースビルドは従来どおりです。

## PSP-1000版の確認状況

- v0.1.4-betaは、PSP-2000/3000/Go向け64MB版とは別のPSP-1000専用ZIPで配布します。
  最大同時数などを32MB RAMに合わせて縮小しているため、PSP-1000版はテスター向けです。
  現在の上限差はゲーム進行を変え得るため、リプレイ互換性やスコアの検証には使用できません。
- PSP-1000向けv0.1.4-beta通常EBOOTを実機で使用し、Normalで1面から6面、幽々子撃破後の
  Ending、スタッフロール、タイトル復帰まで確認済みです。別の実機試験では、4面以降のポーズと
  ゲーム復帰、コンティニューを使い切った後のResult画面、そこからのタイトル復帰も確認済みです。
- 妖夢撃破後、6面へ入らずXMBへ戻っていた問題は、終了済み各面のリプレイ記録領域を
  実使用サイズへ縮小し、面切替前に解放済みテクスチャを実ヒープへ返すことで修正しました。
  Normalの5面→6面遷移はPSP-1000実機で確認済みです。
- 自機側・敵側の会話立ち絵の一部が、PSP画面の最上段へ横一列・1ピクセルだけ出る問題。
  原因は立ち絵の上端ではなく、論理画面を下へ越えた立ち絵の下端が、上下反転された連続フレームバッファの
  次領域へ書き込まれることでした。通常の立ち絵は論理top=16、bottom=526～528で、以前の上端クリップは
  発動していませんでした。下端を論理y=478で座標・UVとも補間クリップする修正へ置き換えました。
  PPSSPPの生480x272出力では、非会話画面1枚と会話中8枚の上端10行がすべて一致し、立ち絵由来の
  最上段差分が消えたことを確認しました。PSP実機での再確認が必要です。

- PPSSPPの32MBモデルでは通常メニューから1面を開始できることに加え、診断用の強制遷移で
  Stage 1～8の連続登録、Result画面、タイトル復帰まで確認済みです。これはExtraとPhantasmの
  通常プレイ、ボス戦、ゲームクリアを確認したものではありません。PSP-1000版は敵64体、弾640発、
  Item 512個、Effect 256個へ上限を下げています。64MB版の敵480体、弾1024発、Item 1100個、
  Effect 400個と異なり、縮小した上限へ到達すると生成されるオブジェクトとゲーム状態が分岐します。
  テスターからも、PSP-1000で試したリプレイのほぼすべてが同期しなかったとの報告があります。
  原作相当の上限を維持できる実装へ直すまで、PSP-1000版のリプレイ同期は保証しません。
- PSP-1000のSEは、半分のサンプルレートへ落とす方式から、全サンプルを保持するG.711 mu-law 8bitへ
  変更済みです。RAM使用量は約796KBのままです。BGMは全機種で原作の44.1kHz・16bit・ステレオPCMを
  直接ストリーミングしており、圧縮は行っていません。PSP-1000実機での音質再確認が必要です。
- PSP-1000で後半面からSTARTを押した際のXMB終了は、ポーズ背景生成時の約1.25MBの一時確保が
  断片化したヒープに収まらないことが最有力原因でした。RGB565フレームバッファから既存テクスチャへ
  直接コピーし、追加ヒープを0にする修正を入れました。未使用だった1MBのCPU側キャプチャコピーも
  削除済みです。PPSSPPの32MBモデルとPSP-1000実機で、4面以降のポーズ・復帰を確認しました。
- コンティニューを使い切った後の結果画面登録で`result.jpg`のRGB24展開用連続領域を確保できず、
  正常終了扱いでXMBへ戻る問題がありました。ゲーム資産の破棄直後に解放済みテクスチャキャッシュを
  実ヒープへ返すよう修正し、部分初期化の巻き戻し、1回の再試行、失敗時のタイトル復帰も追加しました。
  PPSSPPの32MBモデルでは1～6面の累積短縮遷移後に結果画面表示を確認し、結果画像を意図的に壊した
  失敗試験でもスコア保存後にタイトルへ復帰しました。通常のResult表示とタイトル復帰は
  PSP-1000実機でも確認済みです。
- PSP-1000版v0.1.4-betaのEasy、Hard、Lunatic、Extra、Phantasmのクリアは未確認です。
- 参考として、PSP-1000対応前のv0.1.3-betaについては、Gensokyoclubのメンバーから、Lunaticの
  リプレイで5面到達まで確認したとの報告があります。そのリプレイが終了した理由は、残機消尽による
  通常終了か異常終了か判別できておらず、6面到達とゲームクリアは未確認です。この報告は
  PSP-1000版v0.1.4-betaの動作確認には含めません。

## リプレイの既知の問題

- PSP-1000での試験環境として、5.50 GEN-D3と6.61 ARK-5が報告されています。5.50用EBOOTは
  テスターによる自己ビルドであり、配布EBOOTと同一条件ではありません。自己ビルド版の結果は、
  使用したソース、ツールチェーン、ビルド設定、EBOOTのSHA-256が確認できるまで分けて扱います。
- Lunaticのリプレイが幽々子撃破まで完走した後、Replay選択画面へ戻れないとの報告があります。
  再現したPSPの型番と32/64MBビルドは未確定で、原因を調査中です。
- 不具合を再現した場合は、ゲームを再起動する前にメモリースティック直下の
  `TH07PSP_BOOT.LOG`を退避してください。ログは起動するたびに上書きされます。

## その他

- セーブデータとリプレイの互換性・完全性は保証していません。
- PPSSPPで正常でも、Memory Stick I/O、CFW、MECC、メモリ制約に関する実機固有問題が残る場合があります。
