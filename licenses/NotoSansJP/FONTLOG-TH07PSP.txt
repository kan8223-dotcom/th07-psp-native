subset below: its generator and tool version are pinned, and the same result
was independently reproduced from the official Sans2.004 JP OTF above.

Bundled PSP-1000 modified payload
---------------------------------

File: msgothic-subset.ttf
Role: fixed PSP-1000 runtime compatibility filename
Size: 264,288 bytes
SHA-256: c456df98197c895c2919a690c737ab3c4a2924799bb4d92fa3a53849c6b56dec

Despite its compatibility filename, this file is not MS Gothic and contains
no Microsoft font data. It is an OFL Noto Sans CJK JP 2.004 Modified Version.
tools/build_release_noto_subset.py produces it with fontTools 4.62.1 from
either approved Noto source hash above. The input character set is exactly the
1,190 numeric codepoints in src/Th07FontCoverage.hpp (profile SHA-256
da81e0e1a2b8b5d44c135d2ac43f3f91a90ce684c62b985206992e3855a90aa4).

Modification summary:

- delete glyphs outside the 1,190-codepoint TH07 PSP authority;
- retain .notdef plus one mapped glyph per authority codepoint (1,191 glyphs);
- retain only the horizontal GPOS "kern" layout feature and no GSUB feature;
- retain CFF outlines, horizontal/vertical metrics, hinting, and OFL/copyright
  name records 0-6, 13, and 14 in English;
- use deterministic table ordering, bounds recalculation, and no timestamp
  recalculation.

The kern-only candidate matched the full font for all 1,623 unique, non-empty
real Japanese game strings in the local stock-data HarfBuzz audit with
language=ja. Two additional synthetic ASCII/name-entry stress rows accounted
for the only two differences in the 1,625-row audit. Original strings and
original game data were kept local and are not recorded in this repository.

Validation boundary
-------------------

The generator runs two clean builds and requires identical output. Its
--check mode additionally compares the checked-in file, exact cmap, glyph and
table inventory, layout features, legal name records, embedding fsType,
license hash, size, and SHA-256.

Remaining release gate: this exact c456df98... font must still be exercised by
the unified PSP-1000 payload on real hardware through the memory-heavy stage 4
path and the fixed stage 1-6 Lunatic replay, with normal Japanese text and no
allocation, font-coverage, REPLAY INVALID, or fatal errors. PC/PPSSPP and a
different local/private subset do not satisfy that gate.
